# إدارة الشيكات المصرية (`ff_cheque_management`)

إدارة احترافية للشيكات **الواردة والصادرة** في مصر جوه دورة المدفوعات القياسية في
Odoo 18 — من غير نظام محاسبي موازي ومن غير أي تعديل في نواة أودو.

كل شيك دايمًا **دفعة حقيقية واحدة (`account.payment`)** بتتحجز على **حساب وسيط**
قابل للتهيئة، بتتتبع لحد **تاريخ استحقاقها**، ومش بتعتبر محصّلة غير لما تتطابق
من خلال **المطابقة البنكية** القياسية.

- الإصدار: `18.0.1.0.0` — يعمل على Odoo 18.0 Community (وعلى Enterprise)
- يعتمد على: `account` فقط
- الرخصة: LGPL-3
- المستودع: <https://github.com/FlousFlow/ff_cheque_management#main>

---

## 1. المميزات

| المجال | التفاصيل |
|---|---|
| طرق الدفع | **Cheque - Incoming** / **Cheque - Outgoing** (الكود الفني `ff_cheque`) بتتضاف تلقائيًا لكل **جورنال بنكي** |
| بيانات الشيك | الرقم، البنك، تاريخ الشيك، **تاريخ الاستحقاق**، المساحب، ملاحظات — على الدفعة وفي نافذة *Register Payment* |
| تاريخ الاستحقاق | بيحدد `date_maturity` لسطر حساب الشيك في القيد؛ وحالة النضج (*Not Due / Due Today / Overdue / Settled*) بتتحسب لحظيًا |
| دورة الحياة | Received/Issued → Deposited → **Cleared** (بالمطابقة البنكية فقط) / Bounced / Cancelled |
| Mark as Deposited | تتبع تشغيلي فقط (تاريخ + جورنال الإيداع) — **من غير أي قيد محاسبي** |
| Mark as Bounced | محاسبيًا سليم: بيفصل كل التسويات ويلغي بالآلية القياسية. الشيكات اللي سابت حساب الشيكات (محصّلة/مخصومة/مُظهَّرة) بتاخد **قيد رجوع** بدل الإلغاء |
| خصم الشيكات (توريق) | تسلّم الشيك للبنك وتقبض فورًا: `من ح/ البنك (الصافي) + من ح/ رسوم / إلى ح/ حساب الشيكات` — حالة **Discounted**، ولو ارتد بعدين يتسجل الرجوع على العميل |
| تظهير الشيك | تسدّ مستحق مورد بشيك عميلك: `من ح/ الموردين / إلى ح/ حساب الشيكات` — حالة **Endorsed** |
| مساحب الشيك | ربط اختياري للمساحب بـ **Partner** للشيكات من جهة خارجية + زرار *Cheques* على شاشة العميل |
| الداشبورد | كانبان مقسّم بالحالة (**عدد الشيكات في كل عمود**) + Graph + Pivot |
| التنبيهات | يوميًا بينشئ نشاط *Cheque Due* لمدير المحاسبة عن شيكات مستحقة خلال 7 أيام أو متأخرة (وبيتشال تلقائيًا لما تتقفل) + بنر أحمر/برتقالي على الشيك |
| الأمان | تحذير تكرار رقم الشيك بمعرف الدفعة القديمة؛ تفاصيل الشيك بتتجمد بعد التأكيد؛ رفض الحسابات غير القابلة للتسوية أو حسابات العملاء/الموردين |
| تعدد الشركات | حسابات شيك وسطور طرق دفع **لكل شركة** مع فحص صارم للشركة |
| تعدد العملات | مبلغ الشيك = مبلغ الدفعة، وأودو بيتولى التحويل وفروق العملة |

## 2. التهيئة

1. ثبّت **Egyptian Cheque Management** من تطبيقات أودو.
2. افتح **المحاسبة ← الإعدادات ← Cheque Management** (في أول الصفحة بعد
   *Fiscal Localization*) وحدد لكل شركة:
   - **Incoming Cheques Account** — مثال: *شيكات برسم التحصيل*
   - **Outgoing Cheques Account** — مثال: *شيكات صادرة*
   - الشروط المفروضة: مش حساب عملاء/موردين، مش موقوف، **لازم يكون قابل للتسوية
     (Reconcilable)**، ومش الحساب الافتراضي لأي جورنال بنك/نقدي.
3. كل **جورنال بنكي** هياخد طريقتا الشيك تلقائيًا بحساباتك. جورنالات النقدية
   (Cash) عمركم مش هتظهر فيها الشيكات.

> نصيحة: اكتب `cheque` في خانة البحث جوه صفحة الإعدادات هتوصله فورًا.

## 3. القيود الفعلية (مثبتة من الاختبارات)

### شيك وارد (عميل دفع 50,000 بشيك آجل)

| الخطوة | القيد | حالة الشيك |
|---|---|---|
| تسجيل الدفعة بطريقة *Cheque - Incoming* (استحقاق بعد 30 يوم) | `من ح/ الشيكات برسم التحصيل 50,000 (استحقاق = تاريخ الشيك)` / `إلى ح/ العملاء 50,000` | **Received** |
| Mark as Deposited | *(لا يوجد قيد — تتبع فقط)* | **Deposited** |
| المطابقة البنكية مع كشف الحساب | `من ح/ البنك 50,000` / `إلى ح/ الشيكات برسم التحصيل 50,000` | **Cleared** |

البنك مش بيتحرك وقت الاستلام، وحساب الشيك بيرجع صفر بالظبط لما الفلوس توصل.

### شيك صادر (دفعتنا لمورد 30,000 بشيك)

| الخطوة | القيد | حالة الشيك |
|---|---|---|
| تسجيل الدفعة بطريقة *Cheque - Outgoing* | `من ح/ الموردين 30,000` / `إلى ح/ شيكات صادرة 30,000 (استحقاق = تاريخ الشيك)` | **Issued** |
| المطابقة البنكية (سطر كشف الحساب −30,000) | `من ح/ شيكات صادرة 30,000` / `إلى ح/ البنك 30,000` | **Cleared** |

### خصم الشيكات عند البنك (توريق)

*افتح شيك حالته Received/Deposited ← زرار **Discount***

`من ح/ البنك 9,800 + من ح/ رسوم بنكية 200 / إلى ح/ الشيكات برسم التحصيل 10,000`
(القيد يُرحّل وبتسوى سطوره — حساب الشيكات يتحرر فورًا والحالة **Discounted**).
لو البنك رجّع الشيك، زرار *Mark as Bounced* يسجل الرجوع:
`من ح/ العملاء 10,000 / إلى ح/ البنك 9,800 / إلى ح/ الرسوم 200`.

### تظهير الشيك

*زرار **Endorse** على الشيك ← اختر المورد*

`من ح/ الموردين 10,000 / إلى ح/ الشيكات برسم التحصيل 10,000`
— مستحق المورد يتسد بشيك عميلك (الحالة **Endorsed**)، ولو ارتد بعدين
يترجع العميل مدينًا ويترجّع مستحق المورد.

### رفض شيك (قبل المطابقة البنكية)

للمدير المحاسبي فقط. الويزرد بيفصل كل تسويات الدفعة، بيلغيها **بالآلية القياسية**
(القيد بيتلغي ورصيد العميل/المورد بيرجع)، وبيسجل التاريخ والسبب في سجل المحادثة.
الشيك المتطابق بنكيًا بيت refused — افصل سطر الكشف البنكي الأول.

### دفعات جزئية بعدة شيكات

فاتورة 30,000 + ثلاث شيكات × 10,000 ← **ثلاث دفعات مستقلة تمامًا** (الويزرد بيرفض
توزيع شيك واحد على مستندات متعددة)، كل شيك ليها استحقاق ودورة حياة ومطابقة بنكية خاصة.

## 4. القوائم

**المحاسبة ← Cheques**

- **Cheques Dashboard** — كانبان بالحالة (أعداد في كل عمود) + رسم بياني + Pivot
- **Received Cheques** — الشيكات الواردة
- **Issued Cheques** — الشيكات الصادرة

فلاتر: مستحق اليوم / خلال 7 و30 يوم / متأخر / حسب الحالة. تجميع حسب:
البنك، الشريك، شهر الاستحقاق، الجورنال، حالة الشيك، نوع الدفع.

## 5. أسئلة شائعة

**حالة الدفعة (state) ظاهرة Paid والشيك لسه مش محصّل — دي مشكلة؟**
لأ. في Odoo 18 Community الـ state بيتبع تسوية الفاتورة. دورة حياة الشيك
متتبعة لوحدها: `is_matched` / *Cheque Status* بيضلوا Received/Issued لحد ما
المطابقة البنكية تتم فعليًا.

**أقدر أعدل رقم الشيك بعد التأكيد؟** لأ — التفاصيل بتتجمد بعد التأكيد عشان
الاستحقاق في القيد ميبقاش مختلف عن بيانات الشيك. ألغِ وسجل شيك جديد.

**ليه جورنال النقطة مفيهوش شيكات؟** الشيكات ليها معنى على البنوك فقط؛ الموديول
عمره ما بينشئ سطور شيك على الـ Cash.

**تحذير التكرار بيمنعني؟** عمره ما بيمنع — بيحذر بس بمعرف الدفعة الموجودة
(أرقام الشيكات بتتكرر طبيعيًا بين دفاتر عملاء مختلفين).

**عند إلغاء التثبيت** بتتشال الطرق والشاشات وأعمدة البيانات. سطر الطريقة المرتبط
بمدفوعات تاريخية بيتساب (سلوك أودو القياسي) عشان المدفوعات القديمة تفضل مقروءة.

## 6. الاختبارات

35 اختبارًا بتغطي: قيود الوارد/الصارد والاستحقاق، التحصيل للاتجاهين، الشيكات
الجزئية المتعددة، المتأخر، الإيداع (بدون قيود)، تحذير التكرار، الرفض
(مسموح/مرفوض/الصلاحيات)، عدم المساس بالمدفوعات العادية، تحقق الحسابات، عزل
الشركات، الجورنالات الجديدة، حماية الويزرد، دورة حياة تنبيهات الاستحقاق،
**وسيناريوهات التعارضات**: خلط شيكات مع دفعة عادية على نفس الفاتورة، الدفع على
فاتورة مسودة (سلوك الفانيلا بدون تسوية تلقائية)، الربط الكامل بكشف البنك (سطر
الكشف ↔ الدفعة ↔ قيد البنك)، الإيداع في بنك مختلف عن بنك الدفعة، نفس رقم
الشيك على بنكين مختلفين (بدون إنذار كاذب)، دورة إلغاء/إعادة/ترحيل، خصم
الشيكات بالحمايات، التظهير، قيود الرجوع للمحصّل/المخصوم/المُظهَّر (الاتجاهين)،
وربط المساحب بزرار العميل.
